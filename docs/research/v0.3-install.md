## 1. The Marketplace (Home Assistant 2026.11+)

| Fact | Evidence |
|---|---|
| **[Verified]** HACS is built in as the Marketplace from 2026.11.0, set up automatically; the HACS custom integration is blocked | Core `components/marketplace/` exists in 2026.11.0 and 2026.11.2, not in 2026.10.4; official documentation |
| **[Verified]** Administrators only; the first-run warning must be accepted before anything installs | `websocket/*` (`require_admin`); official documentation |
| **[Verified]** A custom repository must be public on GitHub and have `hacs.json` in its root and in every installed version | official documentation; `strings.json` error texts |
| **[Verified]** Keys read from `hacs.json`: `content_in_root`, `filename`, `hacs`, `hide_default_branch`, `homeassistant`, `name`, `persistent_directory`, `zip_release`. Others are skipped silently | `utils/validate.py`, `repositories/base.py` |
| **[Verified]** A repository with both `repository.yaml` and `custom_components/<name>/` is installed as an integration; only a repository with apps and no integration is refused | `repositories/integration.py resolve_content` |
| **[Verified]** Adding a custom repository, and keeping it updated (every 48 h), needs a GitHub connection (device sign-in, read-only); catalog repositories do not | official documentation; frontend `ha-marketplace-repository-dashboard.ts` |
| **[Verified]** Installing over an existing `custom_components/<domain>` moves it aside and restores it if the install fails | `repositories/base.py _async_write_content`; `utils/backup.py` |
| **[Verified]** With releases, the newest stable release is installed; pre-releases only behind a per-repository switch | `repositories/base.py version_to_install`; official documentation |
| **[Verified]** Rollback after an update is a backup restore, not "Install another version" | official documentation |
| **[Verified]** My link `marketplace_repository?owner=&repository=&category=`; the old `hacs_repository` link still works | `redirect.json`; frontend `ha-marketplace-my-redirect.ts` |
| **[Verified]** Catalog (`hacs/default`) requirements include a full GitHub release, the HACS action and Hassfest; a `brand/icon.png` inside the integration satisfies the brand check | `hacs/documentation` `publish/include.md` |

## 2. The app store

| Fact | Evidence |
|---|---|
| **[Verified]** Pre-built images (`image:` in `config.yaml`) are the documented preferred way; locally built apps are discouraged | developer docs `apps/publishing.md` |
| **[Verified]** My link `supervisor_app?app=<slug>&repository_url=<url>` asks to add the repository if needed, then opens the app | frontend `ha-config-app-dashboard.ts` |
| **[Verified]** A repository app's slug is the first 8 hex digits of SHA-1 of the lower-cased URL, `_`, the app's slug: `ce27fbb5_meshbeacon` for this repository. A local app's is `local_meshbeacon`. Each slug has its own data folder | Supervisor `store/utils.py`, `store/data.py` |
| **[Verified]** A backup restores an app into the same slug only; there is no slug rename | Supervisor `backups/backup.py`, `apps/manager.py` |
| **[Verified]** The rating is 8 for MeshBeacon's settings; image signing does not change it (the Supervisor no longer verifies signatures) | Supervisor `apps/utils.py rating_security`, `apps/model.py signed` |
| **[Verified]** An app may call `/discovery` and `/addons/self/*` with no `hassio_api` permission | Supervisor `api/middleware/security.py` |

## 3. The Supervisor's per-app socket

| Fact | Evidence |
|---|---|
| **[Verified]** Supervisor `main` gives each app its own socket, bind-mounted read-only at `/run/supervisor/api/supervisor.sock`, sets `SUPERVISOR_SOCKET`, and identifies the caller by the socket | `docker/app.py`, `api/sockets.py` |
| **[Verified]** The socket file is owned by root, mode 0600; MeshBeacon's core runs unprivileged, so it needs the root relay (ADR 0006 amendment) | `api/sockets.py` |
| **[Verified]** With `supervisor_api_tcp: false`, an app gets no TCP token at all; the token is regenerated at every app start | `apps/app.py`, `apps/model.py` |
| **[Verified]** Supervisor **2026.11.0** gives apps no socket | `docker/app.py` at the tag |
| **[Open]** The first stable Supervisor release with app sockets | Watch release notes; re-verify from source before relying on it |

## 4. The pytest harness

**[Verified]** No `pytest-homeassistant-custom-component` release exists for 2026.11 (newest
0.13.375, pinned to 2026.10.4), and 0.13.375 cannot load Home Assistant 2026.11.2. The unit
harness therefore stays on 2026.10.4. The integration is type-checked against 2026.11.2, and a
real Home Assistant 2026.11.2 runs the smoke test, including the config-entry migration.
