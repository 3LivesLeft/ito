## 1. Two mechanisms, two artefacts

| | App store | Marketplace |
|---|---|---|
| Installs | The **app** (backend container): `meshbeacon/` | The **integration**: `custom_components/meshbeacon/` |
| Provided by | Supervisor, with the frontend's App store pages (`/config/apps/available`) | Core integration `marketplace` (system integration, set up at bootstrap) |
| Needs | Home Assistant OS or Supervised | Any installation type **[Assumption]**: not limited to Supervisor in the code read |
| Source of packages | Git repositories with `repository.yaml` at the root | A catalogue built from `hacs/default`, plus custom GitHub repositories |
| Our status | `repository.yaml` present; images not yet published (M2; RG-1 to RG-12) | `hacs.json` added in M1 (OB-28, `tests/unit/test_hacs.py`); not in the catalogue |

**[Verified]** Each mechanism refuses the other's content:

- The Marketplace raises "*… holds apps, the Marketplace does not install apps*" for app
  repositories (`marketplace/exceptions.py`, `marketplace/base.py`
  `_refuse_what_is_not_managed`).
- In `repositories/integration.py` (`resolve_content`), that error is raised only when no
  `custom_components/<domain>` directory exists *and* a `repository.yaml` or `repository.json` is
  present.
- **[Verified by reading, not by test]** So a single repository holding both, like ours, resolves
  as an integration in the Marketplace and as an app repository in the App store.

## 2. App store (backend)

- **[Verified]** The frontend's My Home Assistant redirect `supervisor_add_addon_repository` opens
  `/config/apps/available` with a `repository_url` parameter, and `supervisor_addon` opens an
  app's page. The quick bar labels the page "App store" (frontend 20261028.6, `app.*.js` chunks and
  the English translation).
- **[Verified]** (HA developer documentation, "Create an app repository", and Phase 0) A
  repository needs `repository.yaml` at its root. Users add the URL in the App store, or follow a
  My Home Assistant link.
- **[Assumption]** The official and community app repositories are curated by their maintainers.
  Listing there is not required: a repository link is enough.

## 3. Marketplace (integration)

**[Verified]** in `homeassistant/components/marketplace/` (2026.11.2):

| Aspect | Behaviour | Where |
|---|---|---|
| Status | Core integration, always set up at bootstrap ("core functionality"). It offers itself through a system discovery flow when no entry exists, and takes over an existing HACS installation | `bootstrap.py`; `marketplace/__init__.py`, `migration.py` |
| Access | Panel is **admin-only**, reached from Settings | `__init__.py` |
| First run | Installing and updating need a warning to be accepted first | `const.py` (`WARNING_VERSION`); translations |
| Catalogue | Built from `hacs/default`, served from `data-v2.hacs.xyz` by default. Optional third-party relays exist for some countries; they are the user's choice | `const.py` (`CATALOG_REPOSITORY`), `profiles.py` |
| Custom repositories | Adding one needs a **GitHub connection** (device-code login, read-only public scope). Browsing and installing from the catalogue do not | `websocket/repositories.py` (`requires_github=True`); config-flow strings |
| Repository manifest | `hacs.json` must be at the repository root **and in every installed version** | Translations: `repository_manifest_not_in_root`, `version_without_repository_manifest` |
| Integration layout | `custom_components/<domain>/manifest.json`, with a domain slug and a version the loader accepts | `repositories/integration.py` |
| Install target | `<config>/custom_components/<domain>` | `repositories/integration.py` |
| Limits | Downloads ≤ 100 MiB; archives ≤ 50,000 members | `const.py` |
| After install | Restart required, raised as a repair issue | `repairs.py`; translations |
| Removal by the catalogue | A repository the catalogue marks **critical** is uninstalled automatically and Home Assistant restarted. A repository removed from the catalogue stays installed without updates | `critical.py`; translations |
| Built-in clash | Replacing a built-in integration needs explicit confirmation | Translations: `replaces_built_in_not_confirmed` |

Consequences for MeshBeacon:

- **Packaging, not features:** v0.3.0 needs a `hacs.json` at the repository root, carried in every
  release. M1 added it; release layout is checked by `tools/check_release.py`.
- **Catalogue listing** means inclusion in `hacs/default`. Until then, users add the repository as
  a custom repository, which needs a GitHub connection. **[Open]** Who governs `hacs/default`, and
  whether CLAUDE.md rule 10 covers it, was not verified. Any submission is made by the maintainer
  personally either way.
- **Catalogue dependency:** a listed integration's updates, and its automatic removal if marked
  critical, depend on the catalogue's governance. Users who prefer not to depend on it can still
  install manually.
- **No new permissions:** the app still never writes to `/config` (architecture §8). The
  Marketplace, not MeshBeacon, installs the integration.
