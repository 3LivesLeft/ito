## Residual risks

- **Same-user process separation.** The core and Reticulum still share a Unix user. A process able
  to ptrace the core could copy its link; AppArmor denies ptrace. In the stand-in container,
  unconfined, the copy attempt also failed, but the reason was not determined (probably Docker's
  default seccomp profile), so it is not counted as a control. Under AppArmor the container test
  asserts it fails. Separate users (and a separate AppArmor profile) are to be designed in an ADR
  before any write-capable credential exists.
- **Relay restarts.** If the relay restarts, the core's link stays broken until the app restarts.
  The integration keeps working, because the key only changes at an app start (SO-1c tests this).
- **Reproducibility across days** is not expected while the Alpine security layer exists;
  promotion makes it unnecessary for integrity ([releasing](../releasing.md)).
- **Home Assistant test environments** (`requirements-ha-*.txt`) are hash-locked but not audited
  in CI: their versions follow Home Assistant's own pins.
- **Everything platform-level** remains open: see the [VM acceptance tests](../testing/v0.3-vm-acceptance.md).
