# ADR 0003: Retain the name "MeshBeacon", with disambiguation

- **Status:** Accepted, conditional (see triggers)
- **Date:** 18 November 2026
- **Evidence:** [Naming research](../research/naming.md)

## Context

An existing, active GitHub organisation called `MeshBeacon` (disaster-response mesh operations,
about 290 commits since February 2026, website `meshbeacon.org`, Discord, logo) uses the same name
in an overlapping problem space with a similar pitch. No registered "MeshBeacon" trademark was
found in aggregator searches, but the official registers have not been searched. The maintainer
prefers to keep the name unless there is a compelling reason to change.

## Decision

Keep **MeshBeacon**, presented as **"MeshBeacon for Home Assistant"**, with:

1. a courtesy contact with the existing MeshBeacon maintainers before the first public release;
2. a tagline that does not echo the existing project's pitch;
3. a distinct visual identity;
4. an official trademark register search (UK IPO, EUIPO, WIPO, USPTO, MyIPO) before v0.1.0 is
   published;
5. a non-affiliation note in the README.

## Rename triggers

Any one of: the existing maintainers object; a conflicting registered mark is found; repeated
user confusion. Decide before the first image is published, because the app slug and image name
are effectively permanent once installed.

## Consequences

The project keeps its chosen identity, accepting some discoverability cost and the risk of a later
rename. The new tagline is an open question (naming Q-22).
